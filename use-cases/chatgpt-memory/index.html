Use case 01

Give ChatGPT a memory that's actually yours.

Persistent, portable, inspectable memory for ChatGPT — stored in your own private space and shared with every other AI tool you use, via one MCP connector.

ChatGPT ships with a built-in memory feature, and it helps — inside ChatGPT. The moment you open Claude, Cursor, or any other tool, that memory stays behind. It is also limited in size, curated by OpenAI's own heuristics, and only partially visible to you.

VeelIQ takes a different approach: memory as a neutral layer that belongs to you, not to any single AI vendor. Connect ChatGPT to your VeelIQ endpoint and it can save facts on request, recall them in any later session, and search your uploaded documents — while the exact same memory serves every other client you connect.

Problem

Every new ChatGPT conversation starts nearly from zero. You re-explain your role, your project, your stack, your preferences. Built-in memory softens this but introduces new problems:

  • Vendor lock-in — memories live inside OpenAI's product and cannot follow you elsewhere.
  • Opacity — you don't fully control what gets stored or how it's used in prompts.
  • No documents — built-in memory stores snippets about you; it does not make your files searchable.
  • Capacity — built-in memory is small and prunes itself unpredictably.

Solution

Add your personal VeelIQ MCP URL as a connector in ChatGPT. ChatGPT then gains native tools backed by your private space:

  • remember — "Remember that our launch is October 3rd" stores a durable fact.
  • recall — next week, in a fresh chat, "When is the launch?" retrieves it.
  • search_knowledge — questions are answered from your uploaded PDFs, with sources.

Because the store is client-agnostic, a fact saved from ChatGPT is instantly available to Claude or your IDE agent. Your memory finally has one home with many doors.

Benefits

  • Conversations start warm: context carries over between sessions automatically.
  • Memory is portable across vendors — switch tools without losing anything.
  • Everything stored is visible and deletable in your dashboard.
  • Document knowledge comes along free: the same connector serves your files.
  • Private by design: row-level security isolation, no training on your content.

Features used

VeelIQ Context: memory (remember / recall), knowledge search over uploaded documents, and workspaces to keep personal and work contexts separate. Everything on this page works on the free Beta plan.

Example

A product manager tells ChatGPT once: "Remember: we decided to keep the free tier at $0 through Beta, decision made June 28." Two weeks later, in a brand-new conversation — or in Claude — they ask "What did we decide about pricing?" The assistant calls recall, finds the fact, and answers with the date and the decision. No scrolling through old chats, no re-explaining.

FAQ

Doesn't ChatGPT already have memory? # +
ChatGPT's built-in memory is real but vendor-locked: it lives inside OpenAI's product, has limited capacity, and cannot follow you to Claude or Cursor. VeelIQ memory is portable, inspectable, and works in every MCP client at once.
How long does setup take? # +
About a minute: sign up free, copy your MCP URL, add it as a connector in ChatGPT's settings.
Can ChatGPT also read my documents through VeelIQ? # +
Yes. The same endpoint exposes search_knowledge, so ChatGPT can answer from your uploaded PDFs with source citations, not just from saved facts.
Is what ChatGPT stores in VeelIQ private? # +
Yes. Facts are stored in your isolated space under row-level security. VeelIQ never sees the rest of your conversation — only the tool calls.
Will Claude see what ChatGPT remembered? # +
Yes, if both clients use your endpoint. That cross-client continuity is the main advantage over any built-in memory.
What does it cost? # +
The Context Beta free plan ($0, no credit card) covers memory and knowledge search under fair-usage limits.
